# freecell.exe / cards.dll: resources and strings, extracted in full

Sources: `/Users/erko/IdeaProjects/xp-cards/freecell.exe` (55,296 bytes, PE32 i386, TimeDateStamp 0x3B7D8476, ImageBase 0x01000000, entry 0x01005438, linker 7.0, subsystem GUI 4.0, OS version 5.1, CodeView NB10 `freecell.pdb`) and `cards.dll` (359,936 bytes, TimeDateStamp 0x3B7DFE43, ImageBase 0x6FC10000).
Tools: pefile with custom decoders for menus, dialogs, accelerators and string blocks, objdump/capstone for cross-references, and Wine 11.18 for live dialog captures.
Scripts are in `research/resx/`: `dump.py`, `dlg.py`, `imgs.py`, `mock.py`, `gen.py` (this file is generated by `gen.py` from `template.md`), `wine/cap2.c` and `wine/hk.c`.
All VAs are absolute (ImageBase 0x01000000). "RVA" means resource data RVA.
Strings are written in **C-literal notation**: `\t` = TAB (0x09), `\n` = LF (0x0A), `\\` = one backslash. Nothing else is escaped. Every resource is LANG 0x0409 (en-US).

## 0. Key takeaways for the clone

* **Main menu "FreeMenu"**: `&Game` (New Game F2, Select Game F3, Restart Game [initially grayed], Statistics F4, Options F5, Undo F10 [initially grayed], Exit) and `&Help` (Contents F1, Search for Help on..., How to Use Help, About FreeCell...). The Help popup has **no** MF_HELP/right-justify flag. The Contents item text really is `"&Contents\t F1"`, with a space after the TAB.
* **Accelerators**: F1 and Shift+F1 map to 106, F2 to 102, F3 to 103, F4 to 105, F5 to 109, F10 to 115, and **Ctrl+Shift+F10 to 114** (the hidden "User-Friendly User Interface" cheat: Abort = win, Retry = lose, Ignore = cancel).
* **Six dialogs**: GameNum, MoveCol, Stats, YouLose, YouWin and Options (numeric id 505). All use `MS Shell Dlg` 8pt. Wine captures of the client areas are in `res/wine_*_client.png`. Mockups of all six are in `res/mock_dlg_*.png`.
* **Original text typos must be kept**: `"Sorry, you lose.There are no more legal moves.\nDo you want..."` (no space after "lose.") and string 307 `"That move requires moving %u cards.You only have enough free space to move %u."` (no space or newline after "cards.").
* **Settings and statistics** live in `HKCU\Software\Microsoft\Windows\CurrentVersion\Applets\FreeCell`. **Every value is REG_BINARY holding 4 bytes** (a little-endian DWORD), not REG_DWORD. The value names are `won lost wins losses streak stype messages quick dblclick AlreadyPlayed`.
* **Statistics migration**: on the first run (when `AlreadyPlayed` is missing), stats are migrated from `entpack.ini`, section `[FreeCell]`, keys `lost won losses wins streak stype`.
* **Help**: HtmlHelpA, loaded dynamically from hhctrl.ocx (ordinal 14). Contents opens `<exe dir>\freecell.chm` with HH_DISPLAY_TOPIC. Search opens the same file with HH_DISPLAY_INDEX. How to Use Help opens `NTHelp.chm`. "What's this" help in the dialogs uses WinHelpW with `freecell.hlp` and the help-ID tables in section 5.8.
* **Window**: class `"FreeWClass"`, style CS_DBLCLKS, background brush **RGB(0,127,0)** (0x007F00), with a 1-px RGB(0,255,0) pen for the cell outlines. On a 2-colour display the background is white and the pen black. WS_OVERLAPPEDWINDOW, default size **640 x min(480, SM_CYSCREEN)** at CW_USEDEFAULT. The title is `"FreeCell"`, then `"FreeCell Game #%d"` once a game is dealt.
* **King**: the 32x32 4bpp bitmaps "KingBitmap" (looks right, toward the home cells), "KingLeft" (looks left, toward the free cells) and "KingSmile" (shown after a win; same pose as KingBitmap, smiling, with a green/blue/magenta palette). The king is blitted at y = (cardHeight-32)/3.
* **cards.dll**: card faces are 71x96. The face bitmap id is `suit*13 + rank + 1` (suit order C, D, H, S; rank 0 = Ace), and the cdt card index is `rank*4 + suit`. Backs are ids 54-65 (24-bpp photos). Red pip cards (A-10 of D and H) get a black 1-px border painted over the red one at draw time. Corners are "rounded" by restoring 3 background pixels per corner.

* The second "use" listed for 320, at 0x10034E3, is a false positive: it is `mov $0x140` (320 px, part of a 320x? size that falls back to 256x192 when SM_CYSCREEN <= 350, in the win sequence), not a string load.
* 311 (`"1 loss"`) and 313 (`"%u losses"`) are reached as 310+1 and 312+1 (`setne cl; add 0x136/0x138` at 0x1002877 and 0x100288F). They are used, not dead.
* 314 `"How to Play"`, 315 `"Commands"`, 316 `"streak"` and 317 `"stype"` have no reference in code and look like leftovers. The registry value names come from inline UTF-16 literals, not from these strings. (UNVERIFIED that nothing loads them indirectly, but there is no computed-id path near them.)
* 319-321 are formatted with `wsprintfW`. `"%u%\n"` and `"%u% \n"` contain a stray `%` that wsprintf swallows, so the output is just the number followed by `\n` or ` \n`. Wine produced `"\tlost:\t\t0\n\n"`. The real XP output is UNVERIFIED but expected to match.
* Percentages are computed by fn 0x1002330: `pct = (won*200 + total) / (2*total)`, i.e. rounded `100*won/total`, with `total = won+lost`. The result is 0 if total == 0. **If lost > 0 and pct >= 100, pct is clamped to 99.**

## 5. DIALOGS

Every dialog is a plain DLGTEMPLATE (not DIALOGEX) with DS_SETFONT and font **"MS Shell Dlg" 8pt**. XP maps that face to Microsoft Sans Serif, and Wine measured dialog base units of 6x13 px at 96 DPI, so 1 DLU = 1.5 px horizontally and 1.625 px vertically. No dialog has DS_CENTER. Instead, the code calls fn 0x1002411 from WM_INITDIALOG to centre the dialog over the main window: `x = mainWnd.left + (mainClient.cx - dlgClient.cx)/2`, `y = mainWnd.top + SM_CYCAPTION + SM_CYMENU + (mainClient.cy - dlgClient.cy)/2`, then `SetWindowPos(..., SWP_NOSIZE|SWP_NOZORDER)`. The template x/y values are therefore irrelevant.

### 10.2 Card index and draw modes (from the disassembly of cdtDrawExt at 0x6FC114F3; jump table at 0x6FC117F3)

* `cd` (card) = `rank*4 + suit`, with rank 0 = Ace .. 12 = King and suit 0 = Clubs, 1 = Diamonds, 2 = Hearts, 3 = Spades. Bitmap id = `suit*13 + rank + 1` (fn 0x6FC11285). At most about 5 face bitmaps are cached at once, with round-robin eviction.
* Modes, with the high bit 0x80000000 of `md` = "don't save/restore the corner pixels":

| md | Name (cards.dll SDK) | Effect |
|---|---|---|
| 0 | mdFaceUp | face bitmap, SRCCOPY, background colour forced to white |
| 1 | mdFaceDown | `cd` is a back bitmap id (54..65), SRCCOPY |
| 2 | mdHilite | face bitmap with **NOTSRCCOPY (0x330008), i.e. colour-inverted**. This is FreeCell's selected-card look. |
| 3 | mdGhost | fill the rect with a brush of rgbBk (PATCOPY), then bitmap 53 with SRCAND (dotted ghost) |
| 4 | mdRemove | fill the rect with rgbBk only |
| 5 | mdInvisibleGhost | bitmap 53 with SRCAND, no fill |
| 6 | mdDeckX | bitmap 67, SRCCOPY |
| 7 | mdDeckO | bitmap 68, SRCCOPY |

* If dx/dy equal the native 71x96, the card is drawn with BitBlt. Otherwise it is drawn with StretchBlt, so cdtDrawExt can scale, but FreeCell never asks it to.
* **Black border on red pip cards**: for md 0 and ids 14..23 or 27..36 (A-10 of diamonds and hearts, whose 1-bpp bitmaps carry a red/white palette and therefore a red border), the DLL PatBlts BLACKNESS lines at top (x+2, y, dx-4, 1), right (x+dx-1, y+2, 1, dy-4), bottom (x+2, y+dy-1, dx-4, 1) and left (x, y+2, 1, dy-4). It then SetPixels black at (x+1,y+1), (x+dx-2,y+1), (x+dx-2,y+dy-2) and (x+1,y+dy-2). **Every card therefore ends up with a black outline whose corners are cut by one pixel.**
* **Rounded corners**: before drawing at native size, fn 0x6FC11095 saves 3 pixels per corner (the corner pixel and its two neighbours along the edges, 12 pixels in total) with GetPixel. Fn 0x6FC11190 restores them with SetPixel afterwards, so the background shows through in a 3-pixel L at each corner.
